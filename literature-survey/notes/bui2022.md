# Bui, Scandariato & Díaz Ferreyra (2022) — Vul4J: A Dataset of Reproducible Java Vulnerabilities Geared Towards the Study of Program Repair Techniques

**Key:** `bui2022` · **Type:** conference paper (data/tool track), MSR 2022, pp. 464–468 · **DOI:** [10.1145/3524842.3528482](https://doi.org/10.1145/3524842.3528482) · **PDF:** not available (closed access; artifact on Zenodo)

**Cluster:** Benchmarks · **Used in:** Method §optional extension; Future work

## What it establishes

Vul4J is a Java vulnerability dataset in which each vulnerability is associated with:

- a **patch**, and
- a **Proof of Vulnerability (PoV) test case** — a test that triggers the vulnerability.

Construction: the authors analysed **1,803 fix commits** from **912 real-world vulnerabilities** in the Project KB knowledge base, ran each application's test suite on the vulnerable and secure versions to identify PoVs, and wrote PoVs themselves when none existed.

Result: **79 reproducible vulnerabilities** from **51 open-source projects**, spanning **25 CWE types**. To their knowledge, the first dataset of this kind for Java, explicitly targeting APR research, where PoVs are needed to identify plausible patches.

## Numbers worth citing

- 1,803 fix commits · 912 vulnerabilities analysed.
- 79 reproducible vulnerabilities · 51 projects · 25 CWE types.

## Why it matters for this thesis

Vul4J is the natural answer to the objection "your application is a toy". It provides real vulnerabilities with **proof-of-vulnerability tests**, which is exactly the O1 oracle the thesis builds by hand for its own app. The optional extension in the method — revert a real fix, let the agent repair it, compare the verdict distribution with the synthetic app — is operationally feasible because of this dataset.

It also validates the thesis's O1 design: the APR community considers a PoV test the minimum evidence that a vulnerability is real and that a patch closes it. The thesis's three-way oracle validation (vulnerable → red, reference fix → green, re-introduced bug → red) is a stricter version of the same idea.

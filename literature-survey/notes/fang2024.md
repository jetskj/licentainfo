# Fang et al. (2024) — LLM Agents Can Autonomously Hack Websites

**Key:** `fang2024` · **Type:** preprint (arXiv:2402.06664) · **DOI:** [10.48550/arXiv.2402.06664](https://doi.org/10.48550/arXiv.2402.06664) · **PDF:** `papers/fang2024_hack-websites.pdf`

**Cluster:** LLM security agents · **Used in:** Related work; motivation; agent design

## What it establishes

LLM agents with tool access — function calling, document reading, recursive self-call — can autonomously attack websites. The paper demonstrates tasks as complex as **blind database schema extraction and SQL injection without human feedback**, where the agent **does not need to know the vulnerability beforehand**. The capability is attributed to frontier models that are highly capable at tool use and code generation.

## Numbers worth citing

- The qualitative capability claims above. The abstract does not give a single success rate, so do not invent one; the full paper reports per-model and per-task results.

## Why it matters for this thesis

The thesis pairs an autonomous repairer with an autonomous attacker (the exploit oracle O1 is scripted, but the framing is agentic). Fang et al. support a key premise: **the loop and the tools matter more than the prompt**. That justifies:

- keeping the repairer's action space small and explicit;
- scripting O1 rather than asking an agent to "try to exploit it" (a scripted replay is a stable oracle; an agent is not);
- treating the agent's *view* (what files, what context) as an experimental variable.

It also sharpens the ethical framing: the same tool loop can attack or repair, so the thesis's contribution — a gate that catches bad repairs — is defensive infrastructure.

## Where to use it

- Related work, agentic security.
- Introduction: one sentence that agents are now capable on both sides.

## Limits

Offensive capability on benchmark websites, not vulnerability repair. It does not measure false accepts or gate reliability. Models and scaffolding are 2024-specific.

# He & Vechev (2023) — Large Language Models for Code: Security Hardening and Adversarial Testing (SVEN)

**Key:** `he2023` · **Type:** conference paper, ACM CCS 2023, pp. 1865–1879 · **DOI:** [10.1145/3576915.3623175](https://doi.org/10.1145/3576915.3623175) · **PDF:** `papers/he2023_sven.pdf` (arXiv:2302.05319)

**Cluster:** Secure code generation · **Used in:** Related work; Discussion (alternative to verification)

## What it establishes

LMs frequently produce unsafe code. The paper studies security along two axes:

1. **security hardening** — make the model more reliable at generating secure code;
2. **adversarial testing** — evaluate the model's security from an attacker's standpoint.

They formulate **controlled code generation**: the model takes a binary property as input and generates secure or unsafe code while preserving functional correctness. **SVEN** learns property-specific continuous vectors that steer generation **without modifying the model's weights**.

## Numbers worth citing

- CodeGen 2.7B generates secure code **59.1%** of the time unaided.
- With SVEN hardening: **92.3%**; with adversarial testing: **36.8%**.

## Why it matters for this thesis

SVEN is the strongest "fix the generator" alternative, and the thesis must acknowledge it. If generation can be hardened to 92.3%, why build a gate? The answer the thesis can defend:

- hardening is probabilistic — 7.7% of generations are still insecure in the reported setting;
- hardening targets the *generator*, while the thesis's gate must judge *any* patch, including one produced by an unhardened model, a different model, or a human;
- the two are complementary: a hardened generator reduces the load on the gate but does not replace the acceptance decision.

The 36.8% adversarial-testing number is also useful: the same mechanism can deliberately produce unsafe code, which is a reminder that "the model said it is fixed" is not evidence.

## Where to use it

- Related work, secure-generation subsection.
- Discussion: "why not just train safer models?" — answer with the residual rate and the generality argument.
- Threats to validity: the thesis evaluates a gate, not a hardened generator, so its results do not depend on model alignment.

## Limits

C/C++ code generation on curated scenarios; SVEN is not a repair or acceptance technique. The percentages are for one model (CodeGen 2.7B) under the paper's protocol and must not be generalised to other models.

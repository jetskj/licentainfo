# Deng et al. (2023) — PentestGPT: An LLM-Empowered Automatic Penetration Testing Tool

**Key:** `deng2023` · **Type:** preprint (arXiv:2308.06782) · **DOI:** [10.48550/arXiv.2308.06782](https://doi.org/10.48550/arXiv.2308.06782) · **PDF:** `papers/deng2023_pentestgpt.pdf` (later version: *PentestGPT: Evaluating and Harnessing Large Language Models for Automated Penetration Testing*)

**Cluster:** LLM security agents · **Used in:** Related work; agent design

## What it establishes

The authors build a benchmark from **real-world penetration-testing targets** and use it to study LLM capabilities. Their finding is nuanced:

- LLMs are proficient at **sub-tasks** — using tools, interpreting output, proposing next actions;
- they struggle to **maintain the whole context** of a testing scenario.

PentestGPT addresses this with **three self-interacting modules**, each handling a sub-task, to mitigate context loss. It reports a **228.6% task-completion increase over GPT-3.5** on the benchmark targets and effectiveness on real targets and CTF challenges. The tool is open source and reports 6,200+ GitHub stars in nine months.

## Numbers worth citing

- 228.6% task-completion increase vs. GPT-3.5.
- Three interacting modules.
- 6,200+ GitHub stars in nine months (adoption signal, not evidence).

## Why it matters for this thesis

The paper's core diagnosis — **context loss is the limiting factor for agentic security work** — is directly relevant to the thesis's design decision to restrict what the repair agent sees (vulnerable function plus one caller level). Two readings:

1. Restriction is realistic: real agents do not get the whole repository.
2. Restriction is a controlled source of variation: it prevents the ceiling effect where the model sees everything and fixes everything.

PentestGPT also illustrates the decomposition strategy the thesis uses: one agent for repair, scripted oracles for judgement, rather than one model doing everything. Decomposition is what makes the failure attributable.

## Limits

Offensive security, not repair. The 228.6% is a task-completion improvement over a specific baseline, not an absolute success rate. The PDF in this repository is a later version with a different title; cite the arXiv record and note the variant.
